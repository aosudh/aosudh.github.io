本次已将无法正常启动的 SN2100 恢复为可登录的 Onyx 3.9.3202。处理过程包括更换串口线、定位 GRUB 引导异常、手动启动原有 ONIE、卸载旧操作系统、安装 Onyx，以及恢复 DHCP 管理和 HTTPS 访问。

“ONIE 重置”在本次操作中具体指通过现有 ONIE 清除旧操作系统并重装。没有重刷 ONIE 固件、重置 BIOS 或修改 EEPROM；GRUB 登录密码也没有被破解或直接重置。

1 故障现象与定位依据

串口无响应与控制平面判断

最初使用 Prolific 串口线连接 COM7，没有可用输出，也无法正常交互。系统状态灯闪烁，RJ45 管理口能够协商链路。更换为 FTDI 线缆后，COM9 立即获得可读控制台，参数为 115200 波特、8 数据位、无校验、1 停止位、无流控。

PHY 建立物理链路并不代表管理 CPU 或操作系统已经工作。最初“电口亮灯但没有返回数据”的现象允许控制平面异常这一可能性；后续可运行 GRUB、ONIE 和安装程序，说明不能据此判定 CPU 已经损坏。原串口链路有问题，但未进一步区分旧线的电气规格、接线或适配器故障。

网络扫描的实际范围

管理口曾直接连接 Windows 的 2.5G 网卡。主机该接口使用 169.254.100.1/16，直连链路协商到 1Gb/s；Wi-Fi 则位于 192.168.10.0/24。抓包及多轮发现没有得到可识别的交换机响应。

随后按要求尝试扩大 ARP 探测范围，完成了 192.168.0.0/16 与 169.254.0.0/16，但扫描中途因适配器或链路错误停止，172.16.0.0/12 与 10.0.0.0/8 没有全部完成。因此不能写成“全部私有网段都已扫描且无设备”。扫描未响应也不能单独证明硬件故障。

更换串口线后发现引导异常

error: unknown filesystem.
Press any key to continue...

设备停在 GRUB 相关错误，而不是完全没有启动。旧菜单可见两个系统项，版本分别为 3.8.2008 和 3.9.1908，以及一个 ONIE 项。当前旧系统无法正常启动，但现有信息不足以确定是此前升级中断、文件系统损坏还是其他原因。

尝试进入 GRUB 命令模式时出现用户名验证。仅尝试一次默认管理员凭据，返回 access denied。随后回到菜单并选择 ONIE，没有进行口令穷举，也没有直接修改 GRUB 密码文件。

可确认与不可确认的边界

可确认的事实对应结论
更换串口线后可以读取并输入原先无串口输出不能作为主板损坏依据
旧系统报 unknown filesystem旧启动链存在异常，需进入恢复环境处理
ONIE 分区可读且能够启动可以利用已有恢复环境，不必先重刷 ONIE
重装读写和双镜像验证通过本次恢复期间未观察到磁盘 I/O 故障；不等同于完整 SSD 健康检测

2 进入 ONIE 并修复启动路径

通过旧系统菜单进入 ONIE

选择 ONIE 后，设备提示该操作将卸载当前操作系统，要求输入 YES。本次确认清除旧系统，并在安装包就绪、校验完成后才继续。屏幕显示以下信息：

OS uninstall has been confirmed.
OS has already been uninstalled - skipping
Loading ONIE ...

这段提示不代表旧分区已经清空。后续在 ONIE 中仍看到旧系统分区，所以依据实际分区表决定是否卸载，未仅凭提示继续安装。

ONIE 自身的 GRUB 没有显示启动菜单

进入第二级 GRUB 后，只出现 grub> 提示符。检查 root、prefix 和目录后，确认 root 为 hd0,gpt2，prefix 为 (hd0,gpt2)/grub。ONIE 内核和 initrd 都存在；/grub/grub.cfg 包含变量与公共函数，但没有可用的 menuentry 启动项。

set
ls
ls (hd0,gpt2)/
ls /onie/
cat /grub/grub.cfg

实际存在的启动文件为 /onie/vmlinuz-0-onie 和 /onie/initrd.img-0-onie。依据本机已有启动参数，在 grub> 下逐条输入：

linux /onie/vmlinuz-0-onie console=tty0 console=ttyS0,115200n8 acpi_enforce_resources=lax acpi=noirq nmi_watchdog=0 boot_reason=rescue
initrd /onie/initrd.img-0-onie
boot

上面的 linux 命令是一条完整命令；文档中的自动换行不表示需要拆开执行。批量写入串口曾导致 GRUB 丢字符，后来改为逐字符发送并间隔约 15 毫秒，才可靠输入长命令。手动操作时应确认整行内容和每次回显。

确认恢复环境和磁盘状态

启动后进入 ONIE rescue，按回车得到 ONIE:/ #。实际版本为 master-201606021913，内核为 3.10.0-54-Mellanox-evb。rescue 模式已禁用安装器自动发现。CPU、内存、SSD 和网口驱动均能够工作。

onie-sysinfo -a
cat /etc/machine.conf
onie-syseeprom
parted /dev/sda unit MiB print
dmesg | grep -iE 'I/O error|ata.*error|EXT4-fs error|failed command'

EEPROM 校验有效；本次启动与读写期间未观察到磁盘 I/O 错误。未运行完整 SMART 或长期压力测试，无法据此排除所有潜在硬件问题。此手动启动方式参考 ONIE 的 x86 GRUB 引导机制。[1]

3 准备安装镜像并卸载旧系统

镜像来源和完整性核对

本次安装包为 X86_64-3.9.3202-installer.bin，大小 831,970,465 字节。安装包来自 ServeTheHome 讨论中公开的社区镜像，使用镜像附带哈希及另一个公开记录交叉核对，同时检查安装脚本和嵌入载荷。没有独立建立厂商签名验证，不能把社区镜像描述成已验证的 NVIDIA 官方下载。[2]

完整文件 SHA256

997f95e89c7617ee3a66e8c877e6ea3dce46b6c5d066a307a8a99fcdabc41514

安装包内嵌载荷 SHA1

62606a46813587539c73e7877bc79fa004b7a938

两个校验值均匹配对应记录。检查发现安装内容包含该平台的内核、rootflop 和 3.9.3202 系统镜像。本次选择可取得并通过完整性检查的版本完成恢复，没有将其表述为最新版本，也没有进行后续跨版本升级。

检查旧分区后执行官方卸载流程

卸载前磁盘为 /dev/sda，包含 GRUB-BOOT、ONIE-BOOT，以及 BOOTMGR 和后续旧系统分区。检查安装脚本发现，本安装路径要求旧分区 3 不存在，否则会拒绝继续。因此先在 ONIE root shell 中执行官方卸载工具：[3]

onie-uninstaller

该命令会清除旧操作系统及其配置，不能作为保留原配置的升级方法。本次目的就是重新安装，未恢复原交换配置。卸载程序自行处理旧分区、引导程序和下一次启动模式，没有使用手工删除分区来替代它。

分区卸载结果
分区 1 GRUB-BOOT保留，磁盘起止位置约 1–3 MiB
分区 2 ONIE-BOOT保留，磁盘起止位置约 3–131 MiB
原分区 3 及后续 OS 分区由 onie-uninstaller 清除

卸载过程中出现以下成功标志，随后自动重启：

Installation finished. No error reported.
Uninstall complete. Rebooting...

重启后 ONIE 仍没有正常菜单，因此再次执行上一节的 linux、initrd、boot 三条命令进入 rescue。使用 parted /dev/sda print 确认仅剩分区 1 和 2，再进入安装阶段。

4 通过本地网络安装 Onyx

建立临时传输连接

安装阶段将交换机 RJ45 管理口直接连接 Windows 网卡。主机已有地址 169.254.100.1/16，在该地址的 TCP 8080 端口启动临时 HTTP 服务，只提供安装包和健康检查。交换机侧给 eth0 设置临时地址，不依赖直连网络上的 DHCP。

端点临时地址与用途
Windows 直连网卡169.254.100.1/16；HTTP 文件服务端口 8080
ONIE 的 eth0169.254.100.2/16；接收安装包
目标文件/tmp/onyx.bin；下载后再次计算 SHA256

以下为本次 ONIE 传输命令，地址已替换为示例值。执行 wget 前，主机 HTTP 服务必须已经启动，并能访问 health 路径。

ifconfig eth0 169.254.100.2 netmask 255.255.0.0 up
wget -T 8 -O - http://169.254.100.1:8080/health
wget -T 30 -O /tmp/onyx.bin http://169.254.100.1:8080/X86_64-3.9.3202-installer.bin
sha256sum /tmp/onyx.bin

交换机端算出的 SHA256 与上一节完整文件哈希完全一致，确认传输没有改变安装包。/tmp 可用空间足够容纳该文件。尝试添加 Windows 主机路由时因权限不足未成功，但实际 HTTP 传输可达，因此没有修改主机路由、防火墙或网卡地址。

执行安装并观察串口输出

onie-nos-install /tmp/onyx.bin

安装器完成校验和解包后，创建临时安装分区并使用 kexec 进入安装环境。此阶段网络连接可能变化，继续通过串口观察进度。安装程序对 /dev/sda 写入系统，生成两套启动与根文件系统位置，并依次验证。操作过程中保持供电，不因长时间写盘而中断。

确认以下输出后，安装过程结束并自动重启：

Image location 1 verified successfully.
Image location 2 verified successfully.
Manufacture done.

我在安装包已经完整下载、开始本地安装后，将管理口接回路由器，因此没有中断文件传输。首次启动时 Onyx 自动生成 GRUB 配置和 SSH 密钥，交换芯片驱动加载成功。临时 HTTP 服务在传输完成后关闭。[4]

本次未执行的操作

没有重新烧写 ONIE、升级 BIOS、修改 EEPROM，也没有单独升级 SSD 固件。安装检查显示 SSD 固件已为 S20728，无需再升级。

5 首次启动和管理配置

完成初始化向导

系统安装后使用默认管理员登录进入初始化流程，主机名设为 sn2100，mgmt0 使用 DHCP，并将设备接回路由器。向导中的 IPv6 默认项保留为启用 IPv6、关闭 SLAAC、启用 DHCPv6。系统原始时钟不正确，已在本次操作中校正。

此版本首次初始化有强制改密流程，所选简单口令被复杂度规则拒绝。现场先使用符合规则的临时口令完成初始化，再按个人实验环境的要求调整密码策略并设置最终管理员口令。公开版省略所有实际口令；复用时应设置自己的密码。

设置指定管理员密码并保存

登录 Onyx CLI 后执行下列命令；它们用于设备已成功启动后的配置阶段，不属于 ONIE 命令。

enable
configure terminal
no password hardening enable
username admin password <YOUR_PASSWORD>
configuration write
show password hardening
show configuration files

验证结果显示策略变更已生效，配置已保存且没有未保存更改。上述示例中的 <YOUR_PASSWORD> 是占位符，需替换为自己的口令；admin 账户的设置不代表其他内置账户使用相同密码。

启用 HTTPS 并验证 Web 登录

本机 HTTPS 原本已处于启用状态，又显式执行开启命令并保存。确认 Web 服务启用、管理 VRF 中监听 HTTPS 443，HTTP 80 保持关闭。[5]

configure terminal
web https enable
configuration write
show web
show interfaces mgmt0 brief

mgmt0 通过 DHCP 获得管理地址，本文以 192.168.10.50/24 示意。通过 HTTPS 使用配置后的管理员凭据完成实际认证，页面进入系统状态界面，并显示主机名 sn2100 和退出入口，验证不限于端口能够连接。

7 许可证与 DAC 后续排查

许可证检查结果

为核对是否需要额外许可证，读取了许可证列表和系统能力。设备没有配置额外许可证，但系统能力已经显示 L2、L3 和 100Gb 最高授权速率。没有找到适用于这台原厂 16 端口 MSN2100-CB2F 的统一“最高级”许可证等级，也没有实际安装额外许可。

show licenses
show system capabilities

现场输出

No licenses have been configured.
Ethernet: Supported, L2, L3

这说明没有观察到限制当前端口到 100G 的许可证门槛；不代表全部高级功能已经逐项验证。其他 OEM 的端口升级 SKU，以及旧 SX 系列的 56GbE 或 VPI 许可，不能直接套用到本机。

自接 DAC 的实际诊断

本次 DAC 两端连接同一台交换机。读取端口后，线缆出现在 Eth1/1 与 Eth1/7，两端读取到相同序列号。自接时也仍需两端的物理规格、速率和配置相互兼容。

诊断指向模块或 PMD 类型不被接受。[6] RSTP 已开启，端口因物理 Down 处于 Disabled/Discarding；没有证据表明生成树导致物理链路起不来。检查中未修改速率、FEC 或其他端口配置。

SN2100 的 100G 使用 4×25G NRZ。部分 QSFP56 被动 DAC 可兼容较低速率，因此不能仅看到 QSFP56 就断言所有此类线缆都不能跑 100G。本次没有查到该精确型号的兼容证明，也未确认线缆损坏。建议用已确认支持 SN2100 的 QSFP28 100GBASE-CR4 DAC 做对照测试；该测试尚未执行。[7]

8 复用流程与证据索引

再次恢复时的执行顺序

先确认串口输出和实际故障，再取得匹配平台且可由 ONIE 安装的 Onyx 镜像并校验。能够进入原 ONIE 时，优先检查现有内核和 initrd；本例因菜单缺失而手动启动 rescue。确认要清除旧系统后，执行 onie-uninstaller，重启进入 ONIE 并核对分区。

网络可达后下载完整安装包，核对设备端 SHA256，再运行 onie-nos-install。等待两套镜像验证和安装完成提示后进行首次配置，最后验证管理登录、配置持久化与硬件状态。不要把文档中的 DHCP 地址、磁盘名或 GRUB 路径直接当作其他设备的默认值。

出现异常时的处理依据

现象优先核对
串口完全没有输出线缆与 console 接口类型、COM 号、115200 8N1、无流控及端口占用
GRUB 只有命令提示符root 和 prefix、分区可读性、实际存在的 ONIE 内核和 initrd 路径
安装器拒绝旧分区布局分区表及对应安装包要求，确认卸载流程是否完成
下载或 SHA256 不一致文件服务、网口地址、传输完整性；校验一致前不继续安装
安装后端口仍 Down分别检查管理状态、线缆 EEPROM、link-diagnostics、速率和 FEC

本地原始证据

工作目录 work 中保留了 com9-initial-console.txt、com9-session.log 和 com9-recovery-session.log，分别记录初始错误、早期 GRUB 交互和后续恢复串口输出。原始串口日志含 ANSI 控制字符，不宜直接作为排版后的操作手册。

onyx-installer-verification.json 保存安装包大小、哈希、来源与载荷检查结果；onyx-installer-script-inspection.txt 保存脚本检查内容。网络探测和 Web 验证另有对应记录。本文只摘录关键证据，没有附入临时口令或会话凭据。
