本文汇总 **950PR 84G**、**RTX 6000D** 与 **RTX PRO 6000 Server** 三张单卡加速卡的全栈实机对比结论，覆盖底层原生低精度矩阵算力、20 项主流大模型算子与板载显存带宽，以及大语言模型推理（Qwen3.8-27B Dense / Qwen3.6-35B-A3B MoE）、音视频生成（MiniMax H3 / Wan 2.2）和多模态理解（VLM）的完整端到端表现。

> [!NOTE]
> 关于 RTX 6000D 与满血 RTX PRO 6000 Server 在芯片物理规格、Tensor Core 发射级限速（`~37%`）与 DCGM 底层计数器层面的深度归因，可对照站内另一篇 [RTX PRO 6000 vs RTX 6000D 实测报告](/posts/rtx-6000d-vs-pro-6000/)。

## 00 · 核心结论、全景图与全栈 Roofline 分析

### 00.1 核心结论与跨负载全景对比

六大核心实测结论速览：
- **低精度矩阵算力（8192³ GEMM）**：三卡统一 **MXFP4** 格式下，950PR 84G / 6000D / PRO 依次为 **1,456.0 / 533.9 / 953.0 TFLOP/s**；NVIDIA 原生 **NVFP4（b12x）** 下 PRO 可达 **1,550.2 TFLOP/s**。
- **板载显存带宽（4 GiB Triad）**：**PRO 1.489 ＞ 6000D 1.302 ＞ 950PR 84G 1.252 TB/s**；16 MiB 小工作集片上 L2 缓存带宽分别达 `7.33 / 6.02 / 4.89 TB/s`。
- **27B 稠密模型（Qwen3.8-27B-FP8）**：PRO 全面领先；开启 MTP3 后短输入 C1 达 `98.9 / 101.5 / 113.4 tok/s`；**8K–32K 长上下文下 950PR 84G 显著反超 6000D**（32K C1：`31.53 vs 19.89 tok/s`）。
- **35B MoE 模型（Qwen3.6-35B-A3B-FP8）**：低并发 NVIDIA 占优；单并发下 950PR 84G 开启 MTP3 将吞吐从 `63.40` 提升至 **`128.68 tok/s`（2.03×）**，C16 达 `1,190.89 tok/s`；算子拆解显示 MoE 矩阵乘仅占总核时间约 20%，稠密投影与步间调度占大头。
- **音视频生成（MiniMax H3 & Wan 2.2）**：一致梯队 **PRO ＞ 950PR 84G ＞ RTX 6000D**。MiniMax H3 生成 5.17 秒有声视频耗时 `80.89s / 120.30s / 197.53s`（950PR 84G 为 6000D 的 `1.64×`）；Wan 2.2 文生视频 `169.9s / 237.0s / 403.8s`。
- **多模态理解与输出质量**：200 题 GSM8K 回归得分均位于 `92.5%–97.0%` 正常区间；64 帧多模态长输入（15,880 tokens）下 950PR 84G 端到端 `10.60s`，与 6000D（`10.63s`）基本持平。

### 00.2 全栈 Hardware Roofline 总图：3 分钟看透三卡本质

将三张卡的实测显存带宽斜线、BF16/FP8/FP4 算力屋顶，与小到大矩阵（`M = 1 ~ 8192`）及真实大模型解码工作点叠绘在同一对数坐标系中，即可穿透表层跑分，一眼看清各类业务究竟受限于**显存墙、调度墙还是算力墙**：

![三卡全栈 Hardware Roofline 总图](/assets/950pr-vs-rtx6000/roofline-fullstack.png "图 0-2：三卡全栈 Hardware Roofline 总图。实线为 BF16 Roofline，虚线为 FP8 算力延伸，点线为 FP4 峰值参考；散点为实测 BF16 GEMM 轨迹与 27B/35B 真实解码工作点。")

1. **① 显存带宽墙（27B Dense 解码）**：27B 稠密模型单并发解码（`AI ≈ 2 FLOP/B`）紧贴显存斜线下方，三卡带宽利用率均达 **~80%**，因此短输入 C1/C4 性能严格按板载带宽 `1.49 : 1.30 : 1.25` 排布。
2. **② 低并发调度 / 小核墙（35B MoE C1）**：35B MoE 单并发有效算力显著掉落在斜线下方（`950PR 84G 仅 0.37 TF vs PRO 1.15 TF`）——此时既未打满显存也未触及算力，瓶颈在于稀疏路由碎片化与步间空隙，需靠 **MTP3 或高并发（C16）** 将其拉回效率区。
3. **③ 计算算力墙（视频扩散 / 长序列预填充）**：高算术强度区（`AI ＞ 110`）RTX 6000D 因 BF16 屋顶最低（`141 TF`）率先撞墙；**950PR 84G（373 TF）** 与 **PRO 6000（444 TF）** 持续爬升，直接决定了二者在 32K 长上下文、MiniMax H3 与 Wan 2.2 中大幅领先 6000D。

#### 四大性能根因总结
1. **实际走 MXFP8 极小批量分组乘，无法按 FP4 峰值折算**：Trace 证实 950PR 84G 上模型权重实际运行在 **MXFP8（`FP8 E4M3FN + E8M0`）与 BF16** 路径。模型共 40 层、每层 256 专家（Top-8），C1 / C16 每层仅产生 `8 / 128` 条路由 Token，单个活跃专家分摊极少，处于访存与启动延迟主导区。
2. **MoE 专家矩阵乘仅占约 20%，稠密投影与辅助层占大头**：950PR 84G 默认 C1 总核时间 `64.65 ms` 中，稠密投影/共享专家/门控/LM Head 占 **31.9%**，路由分发与动态量化占 **15.8%**，逐元素与布局占 **13.9%**，GDN 占 **7.8%**，MoE 分组 Gate/Up/Down 合计仅 **20.3%**；PRO 6000 同样呈现非 MoE 线性层大于融合 MoE 的分布。
3. **低并发步间存在明显空闲，高并发下趋于打满**：950PR 84G 在 C1 下单步跨度 `10.94 ms` 中含 `2.80 ms` 步内无核空隙，8 步图外间隔达 `79.8 ms`；并发增至 C16 后步内空隙几乎归零（`0.06 ms`），硬件利用率大幅改善，吞吐随并发线性攀升至 `1,190+ tok/s`。
4. **GDN 原生算子已生效，MTP3 以低开销草稿换取 2× 产出**：实测 Trace 记录到原生 `CausalConv1d` 与 `aclnnRecurrentGatedDeltaRule` 正常调用（每 8 步各 240 次），启动日志中的 KDA 警告属于未触发的无关分支。MTP3 每 8 次目标验证配合 24 次 Draft 前向（合并为 16 次图启动），在合成压测中草稿接受率达 `69.1%`，将单请求输出速度翻倍。
